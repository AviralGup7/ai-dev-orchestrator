## 1. The bug: a dead run rendered as a healthy one

### What the docs actually say

Fetched `developer.chrome.com/.../service-workers/lifecycle` directly. Three
termination conditions, still current:

- after **30 s of inactivity** — any event or extension API call resets it
- when **a single request takes longer than 5 minutes** to process
- when a `fetch()` response takes more than 30 s

**The claim I had been carrying was subtly wrong.** The Chrome 110 blog post
says the hard five-minute *maximum lifetime* was removed. That is a different
statement from the second bullet, which is still in force. A worker may now
live indefinitely *across many events*; a **single request still cannot exceed
five minutes**. Chrome 116 exempted four APIs (`desktopCapture`,
`launchWebAuthFlow`, `management.uninstall`, `permissions.request`) — we use
none of them.

So eviction during a long engineer phase is **expected, not exceptional**.

### What happened on eviction

| Fact | Evidence |
|---|---|
| The run is a detached promise (`activeRun`) | `background.js:520` |
| Eviction destroys it silently | MV3 semantics |
| Nothing restarts it | **no `chrome.runtime.onStartup` handler exists anywhere** |
| The record still says `state: 'running'` | it is persisted, the worker is not |

Demonstrated by running `resumability()` against an evicted-run record:

```
20 min after eviction: {"resumable":true,"requiresUser":false,
                        "why":"resumes iteration 1 at the plan phase"}
```

For six hours the user is shown a **green live dot, a counting clock and a
promise of clean resumption** for a run that stopped existing. Consistent with
the reported "stuck at 05:56".

### The signal was already there and was being discarded

`chrome.storage.local.set({'orchestrator-heartbeat': Date.now()})` ran every
20 s. `grep` across `src/`, `extension/`, `test/` and `tools/` found **exactly
one occurrence: the write.** Nothing read it — a dead field, the same class as
`failedAttempts`.

Reading it is the whole fix. `HEARTBEAT_STALE_MS = 90_000` (three missed
beats). Deliberate properties:

- **an unknown heartbeat never raises an alarm** — `null`/`NaN`, or a record
  predating the field, returns "not abandoned". Absence of evidence is not
  evidence of death.
- **a live run beats the check indefinitely.** The engineer may take hours; the
  heartbeat ticks throughout. This is *not* a work timeout.
- **written immediately on start**, not first after 20 s — otherwise a run
  evicted at t+5 s reads as abandoned.
- the panel **drops the live dot** and states the cause and the remedy.
- `history` and `snapshot` use the same evidence, so two views cannot disagree.

## 2. Confirmed correct — do not re-investigate

| Claim | Verdict | Source |
|---|---|---|
| `storage.local` 10 MB, 5 MB before Chrome 114 | correct — and we hold `unlimitedStorage`, so `QUOTA_BYTES` does not apply at all | chrome.storage reference |
| `minimum_chrome_version: "114"` | correct; `chrome.sidePanel` sets the floor | manifest + sidePanel docs |
| `executeScript` `func` loses its closure | **confirmed verbatim**: "This function will be serialized… any bound parameters and execution context will be lost" | chrome.scripting reference |
| `arena.ai/agent/<uuid>` is a real URL shape | confirmed — Agent Mode launched June 2026 | arena.ai/blog/agent-mode, help.arena.ai |
| Dynamic `import()` banned in a service worker | confirmed; none reaches the worker | grep + w3c/ServiceWorker#1356 |
| 30 s idle timer, reset by any API call (Chrome 110+) | correct | lifecycle doc |

The closure finding is worth noting twice: it is the exact bug caught in the
previous session by reasoning, and the official reference states it outright.

## 3. False alarms — recorded so they are not chased again

**`DEFAULTS` is exported by both `stop.js` and `dom.js`.** An automated scan
flagged this as a bundle name collision, which was a real fatal class in this
project's history. It is **not** one here: `build-extension.mjs` copies
separate ES modules and rewrites import specifiers — it never concatenates.
Verified by reading the build and by `node --check` on all 56 dist files.

**Top-level `await` in `popup.js` and `sidepanel.js`.** Legal in a document,
fatal only in the worker. Neither is the worker. `check-loadable.mjs` already
reports this as a note.

**Coverage "regression" to 78 %.** Not a regression — the earlier 76.09 %
figure predates the session-12 tests.
